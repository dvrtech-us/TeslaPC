# List-view file browser with watched/resume badges

- Date: 2026-06-27
- Feature: media/file-browser-vlc
- Related code: `TeslaPCInterface/WebServer.cs`, `TeslaPCInterface/MediaLibrary.cs`,
  `TeslaPCInterface/style.css`, `TeslaPCInterface/list.html`

## Context

The previous file browser rendered a `.grid` of `.tile` cards — a visual style suited to a
small number of items in a square layout. As video libraries grew, the grid had two problems:

1. **Density.** A tile grid uses significant vertical space per item. On a portrait-oriented
   Tesla screen a folder with many files required extensive scrolling.
2. **No playback state.** There was no way to tell at a glance which files had been watched or
   how far the Client had progressed, even after `MediaLibrary` was introduced.

The goals of this change were to increase information density and surface per-file playback
state without adding a separate "library" page.

## Decisions

### List view (`.list` / `.row`) replacing the tile grid

Each item is now a full-width `<a class="row …">` row rather than a fixed-size `.tile` card.
Rows are significantly more compact vertically, allowing many more files to be visible at once
on the Tesla's tall-but-narrow display. The row layout was chosen over a table because it is
easier to style responsively and aligns with the existing flexbox conventions in `style.css`.

The old `.grid`/`.tile` CSS is retained in `style.css` but is no longer generated by
`returnAllFilesAsHtmlLinks`. Removing it was deferred to avoid breaking anything that might
reference those classes externally and to keep the diff minimal.

### Full filename including extension

The previous tile showed the filename stem (without extension) to save space. The list row
has enough horizontal room to show the full `Path.GetFileName` result (stem + extension).
This is more useful when the Client has multiple files with the same stem but different
extensions (e.g. `.mkv` and `.srt`).

### Watched/resume badges from `MediaLibrary.GetAll()`

`MediaLibrary.GetAll()` is called once per `/list.html` render, returning a dictionary keyed
by lower-cased path. The per-file lookup during HTML generation is a dictionary key access —
O(1) per file, O(n) total, one DB round-trip per page render. This is preferable to calling
`Get(path)` per file (N round-trips) for the expected library size.

Three badge states were chosen:
- **Watched** (`badge done`, green): the file has been fully watched (≥ 95 %). The row also
  receives the `watched` CSS class so the entire row can be styled (e.g. dimmed text).
- **Partial** (`"{percent}%"`): the file has a saved position but is not watched. The numeric
  percentage gives the Client a quick sense of how far they got.
- **None**: no record or 0 % — treated as not started; showing "0%" would be noise.

### `--good` color token

A `--good` CSS custom property was added to `style.css` for the watched check icon and
`badge done` background. Centralizing the color in a token avoids duplicating a hex value
across multiple selectors and makes future theme changes straightforward.

## Consequences

- **Positive:** More files visible per screen — approximately 3× the density of the tile
  grid for typical filenames.
- **Positive:** Watched and in-progress files are immediately distinguishable without opening
  them.
- **Note:** The `.grid`/`.tile` CSS remains in `style.css`. It can be removed in a future
  cleanup once confirmed no other page references it.
- **Note:** `returnAllFilesAsHtmlLinks` now depends on `MediaLibrary`. If `GetAll()` fails
  (exception caught and logged by `MediaLibrary`), it returns an empty dictionary and all
  files render without badges — the page is still functional.
