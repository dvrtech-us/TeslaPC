# Audio Capture

`/ws/audio` sends one text frame from `format_message`, then binary PCM. Fields are `type` (`format`), `sampleRate`, `bitsPerSample`, `channels`, and `sampleFormat` (`float`, `pcm16`, `pcm24`, or `pcm32`).

Silence is covered with keepalive noise, not zero PCM, so the remote player (the Tesla browser) does not switch audio source during short silences. `decisions/audio.rs` holds the pure functions:

- `is_silent(pcm)` is true when every byte is zero (float and integer PCM).
- `cover_silence(silent_ms)` is `silent_ms < SILENCE_MAX_MS` (`10000`).
- `keepalive_noise(nbytes, bits_per_sample, is_float, seed)` returns xorshift32 white noise in the capture sample format (32-bit float, 32/24/16-bit integer) with peak `KEEPALIVE_NOISE_AMPLITUDE` (`1/4096`, about -72 dBFS). An unknown sample width returns zeros.
- `should_inject_silence` is true when `capturing`, not `media_mode`, `has_clients`, `typical_buffer_bytes > 0`, the queue is empty, `idle_ms >= SILENCE_START_MS` (`250`), and `cover_silence(silent_ms)`. `typical_buffer_bytes` is only a gate (must be above zero); it no longer sets the buffer size. The task `silence_keepalive` in `routes.rs` sleeps `KEEPALIVE_POLL_MS` (`20`) and measures the real time since the previous tick, because the sleep overshoots (about `30` ms on the lab laptop). Each injected buffer is `PcmHub::noise(keepalive_bytes(elapsed_ms, sample_rate, bits_per_sample, channels))`, pushed with `real=false`, using the announced `audio_format`. `keepalive_bytes` returns whole frames for `elapsed_ms`, capped at `KEEPALIVE_MAX_CHUNK_MS` (`100`) so a stalled task cannot queue a burst. If the format lock fails the size is `0` and `push` drops the empty buffer.

`KeepaliveInput` carries two clocks: `idle_ms` (time since any captured packet) and `silent_ms` (time since the last captured packet that held sound). After `10` s of continuous silence the noise stops and silence is sent as captured (or not at all if the device sends no packets).

`PcmHub` (`state.rs`) holds `last_real`, `last_sound`, `sample_kind` (bits, is_float; default `32`, float), and `noise_seed`. `set_sample_kind` is called by `run_loopback` and the Linux `start_audio`. `PcmHub::push(bytes, real=true)` updates `last_real` and `typical_bytes`; a packet with any non-zero byte updates `last_sound`; an all-zero packet is replaced with noise of the same length while `cover_silence(silent_ms())`, and forwarded unchanged after that. Noise is never mixed into packets that contain sound. ffmpeg media playback pushes with `real=true`, so its all-zero packets get the same treatment.

Windows `win_capture::run_loopback` opens the default render endpoint (`GetDefaultAudioEndpoint(eRender, eConsole)`), initializes it with `AUDCLNT_STREAMFLAGS_LOOPBACK`, sets `capturing`, stores a nominal `typical_bytes` from the mix format, and pushes each packet. A packet flagged `AUDCLNT_BUFFERFLAGS_SILENT` (`0x2`) has undefined buffer content, so it is pushed as zeros of `count * nBlockAlign` bytes. `describe_wave` reads the mix format; for `WAVE_FORMAT_EXTENSIBLE` (`0xFFFE`) it reads the SubFormat GUID at offset 24 and treats it as float when `sub.data1 == 3` (`KSDATAFORMAT_SUBTYPE_IEEE_FLOAT`). Float is announced as `float`, never `pcm32`. `win::start_audio` runs `run_loopback` in a retry loop on the `WasapiLoopback` thread. When an attempt ends (no render endpoint at boot, `AUDCLNT_E_DEVICE_INVALIDATED`, any other error) it sets `pcm.capturing` false, logs `[Audio] WASAPI loopback unavailable: <error>. Retrying.` only when the error text differs from the last logged one, waits `loopback_backoff_ms` (`1` s, `2` s, `4` s, `8` s, then `10` s; a run longer than `30` s restarts at `1` s and also lets a repeated error text be logged again), and starts again from `GetDefaultAudioEndpoint`, so a new default device is picked up. `run_loopback` calls `CoInitializeEx(COINIT_MULTITHREADED)` each attempt and balances it with `CoUninitialize` through the `ComScope` guard, which is declared before the COM objects and so drops after them. A real OS failure is logged and the socket still announces the default format (`48000`, `32`, `2`, `float`). Linux runs `parecord` on the default sink's `.monitor`.

While a file is playing, `pcm.media_mode` suppresses loopback and `playback::audio_reader` pushes the file's PCM on the same queue. Stop clears the flag.

The browser player is `teslapc/assets/PCMPlayerProcessor.js`.
