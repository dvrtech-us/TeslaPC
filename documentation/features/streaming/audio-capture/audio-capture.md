# Audio Capture

`/ws/audio` sends one text frame from `format_message`, then binary PCM. Fields are `type` (`format`), `sampleRate`, `bitsPerSample`, `channels`, and `sampleFormat` (`float`, `pcm16`, `pcm24`, or `pcm32`).

Silence is covered with keepalive noise, not zero PCM, so the remote player (the Tesla browser) does not switch audio source during short silences. `decisions/audio.rs` holds the pure functions:

- `is_silent(pcm)` is true when every byte is zero (float and integer PCM).
- `cover_silence(silent_ms)` is `silent_ms < SILENCE_MAX_MS` (`10000`).
- `keepalive_noise(nbytes, bits_per_sample, is_float, seed)` returns xorshift32 white noise in the capture sample format (32-bit float, 32/24/16-bit integer) with peak `KEEPALIVE_NOISE_AMPLITUDE` (`1/4096`, about -72 dBFS). An unknown sample width returns zeros.
- `should_inject_silence` is true when `capturing`, not `media_mode`, `has_clients`, `typical_buffer_bytes > 0`, `no_packet_since_tick` (no captured packet since the previous keepalive tick; `PcmHub::take_idle_tick` reads and clears `pushed_since_tick`, which each `push(.., real=true)` sets), `idle_ms >= SILENCE_START_MS` (`250`), and `cover_silence(silent_ms)`. `typical_buffer_bytes` is only a gate (must be above zero); it no longer sets the buffer size. The task `silence_keepalive` in `routes.rs` sleeps `KEEPALIVE_POLL_MS` (`20`) and measures the real time since the previous tick, because the sleep overshoots (about `30` ms on the lab laptop). Each injected buffer is `PcmHub::noise(keepalive_bytes(elapsed_ms, sample_rate, bits_per_sample, channels))`, pushed with `real=false`, using the announced `audio_format`. `keepalive_bytes` returns whole frames for `elapsed_ms`, capped at `KEEPALIVE_MAX_CHUNK_MS` (`100`) so a stalled task cannot queue a burst. If the format lock fails the size is `0` and `push` drops the empty buffer.

`KeepaliveInput` carries two clocks: `idle_ms` (time since any captured packet) and `silent_ms` (time since the last captured packet that held sound). After `10` s of continuous silence the noise stops and silence is sent as captured (or not at all if the device sends no packets).

`PcmHub` (`state.rs`) holds `tx` (a `tokio::sync::broadcast::Sender<Bytes>` with capacity `PCM_BROADCAST_CAPACITY` = `64` chunks, about `640` ms at 10 ms chunks), `pushed_since_tick`, `last_real`, `last_sound`, `sample_kind` (bits, is_float; default `32`, float), and `noise_seed`. `set_sample_kind` is called by `run_loopback` and the Linux `start_audio`. `PcmHub::push(bytes, real=true)` updates `last_real` and `typical_bytes`; a packet with any non-zero byte updates `last_sound`; an all-zero packet is replaced with noise of the same length while `cover_silence(silent_ms())`, and forwarded unchanged after that. With no `/ws/audio` client (`client_count == 0`) `push` returns before sending; otherwise it calls `tx.send` directly (no intermediate queue or dispatch task). Noise is never mixed into packets that contain sound. ffmpeg media playback pushes with `real=true`, so its all-zero packets get the same treatment.

Windows `win_capture::run_loopback` opens the default render endpoint (`GetDefaultAudioEndpoint(eRender, eConsole)`), initializes it with `AUDCLNT_STREAMFLAGS_LOOPBACK`, sets `capturing`, stores a nominal `typical_bytes` from the mix format, and pushes each packet. A packet flagged `AUDCLNT_BUFFERFLAGS_SILENT` (`0x2`) has undefined buffer content, so it is pushed as zeros of `count * nBlockAlign` bytes. `describe_wave` reads the mix format; for `WAVE_FORMAT_EXTENSIBLE` (`0xFFFE`) it reads the SubFormat GUID at offset 24 and treats it as float when `sub.data1 == 3` (`KSDATAFORMAT_SUBTYPE_IEEE_FLOAT`). Float is announced as `float`, never `pcm32`. `win::start_audio` runs `run_loopback` in a retry loop on the `WasapiLoopback` thread. When an attempt ends (no render endpoint at boot, `AUDCLNT_E_DEVICE_INVALIDATED`, any other error) it sets `pcm.capturing` false, logs `[Audio] WASAPI loopback unavailable: <error>. Retrying.` only when the error text differs from the last logged one, waits `loopback_backoff_ms` (`1` s, `2` s, `4` s, `8` s, then `10` s; a run longer than `30` s restarts at `1` s and also lets a repeated error text be logged again), and starts again from `GetDefaultAudioEndpoint`, so a new default device is picked up. `run_loopback` calls `CoInitializeEx(COINIT_MULTITHREADED)` each attempt and balances it with `CoUninitialize` through the `ComScope` guard, which is declared before the COM objects and so drops after them. A real OS failure is logged and the socket still announces the default format (`48000`, `32`, `2`, `float`). Linux runs `parecord` on the default sink's `.monitor`.

While a file is playing, `pcm.media_mode` suppresses loopback and `playback::audio_reader` pushes the file's PCM through the same `push`. `audio_reader` collects ffmpeg's stdout and pushes chunks of `audio_chunk_bytes(sample_rate, frame_bytes)` = `sample_rate / 100 * frame_bytes` (10 ms, whole frames, never `0`; 48000 Hz float stereo is `3840` bytes, 44100 Hz pcm16 stereo is `1764`). When ffmpeg's output ends, the remaining whole frames are pushed as a final partial chunk if the generation is still current. Stop clears the flag.

`audio_socket` (`routes.rs`) sends the format frame, then calls `pcm.tx.subscribe()`. Each client gets chunks from its own receiver. A client more than `64` chunks behind gets `RecvError::Lagged(n)`, logs `[Audio] client lagged; skipped <n> chunks` at info level, and continues from the oldest chunk still held; `Closed` ends the socket. Slow clients therefore get recent audio and cannot stall the others. The socket also reads client text frames: `client_stats_line` accepts JSON with `"type":"stats"` of at most `CLIENT_STATS_MAX_BYTES` (`512`) and the browser sends one every 10 s with `bufferedMs`, `minMs`, `underruns`, `trims`, `contextRate`. It is logged at info level as `[Audio] client buffered=<n>ms min=<n>ms underruns=<n> trims=<n> rate=<n>`; missing or non-numeric fields print `?`. Any other frame is ignored.

The browser player is `teslapc/assets/PCMPlayerProcessor.js`.
