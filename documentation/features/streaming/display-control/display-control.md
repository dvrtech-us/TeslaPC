# Display Control

`GET /display/info`, `/display/match?w=&h=`, and `/display/set?w=&h=` return `{ changed, width, height, modes: [{ w, h }] }`.

`/display/match` calls `decisions::display::fit_viewport(modes, vw, vh)`, where `w` and `h` are the browser stream area in device pixels (`clientWidth/Height x devicePixelRatio`). Among modes at least 480 lines tall that cover the area in both directions, the closest aspect wins and a near-tie (within `0.01`) goes to the smallest area. If no mode covers the area, the closest aspect wins and a near-tie goes to the largest. The stream height is the height the picture occupies in the area when fitted by aspect, never above the mode height, at least `240`, then `clamp_stream_height`. `display_action` sets the mode if it differs, then, only when the chosen mode is the active one, saves and applies the stream height with `save_stream_height` (the same `.env` write as `POST /config`, `TESLAPC_STREAM_HEIGHT`). The response adds `streamHeight`, and the log line is `[Display] Fit viewport <vw>x<vh> -> mode <w>x<h> (changed: <bool>), stream height <h>`. `best_for_aspect` is no longer used by the server (only re-exported and covered by tests); `match_max_height` is removed. Only driver-listed modes can be chosen (a custom mode added in the graphics driver's tool appears in the list); a larger picture uses more data. Verified on the lab laptop: `/display/match?w=1200&h=774` changed 720x480 to 1280x800, set the stream height to 750, and `/stream` delivered 1200x750 frames with DXGI reopened in place. The desktop changes only when the chosen mode differs. `try_set_mode` uses `ChangeDisplaySettingsW`. A refused change returns the current mode and `changed: false`.

The Settings page resolution buttons (`480`, `720`, `1080`) post `streamHeight` only on tap. They do not change the desktop. Fit screen is the only action that changes both the mode and the stream height. The main page has no resolution control. Its Fit screen button calls `/display/match`; because `changed: false` also covers a refused mode change or no eligible mode, the page says `Unchanged <w>x<h>`, not that the display already fits. The server does not restore the previous display mode or stream height.

Linux `display_snapshot` runs `xrandr --query` and `wlr-randr`, then `choose_display_query`. Wayland prefers the wlr-randr mode list. `try_set_mode` uses `display_set_args`: `wlr-randr --output <name> --mode WxH` when the session is Wayland and wlr-randr returned modes, otherwise `xrandr --output <name> --mode WxH`. A failure returns `changed: false`.
